Why this is called k-anonymity

A naive breach checker asks the server “is this password breached?” — which hands your secret (or a trivially crackable hash of it) to a third party and to anyone watching the wire. A password you were worried about is now a password somebody else has.

k‑anonymity flips the question around. Instead of asking about one hash, you ask for a bucket: “give me every breached hash that starts with 5BAA6.” The server has no way to know which of the ~2,000 answers you cared about, or whether yours was in the list at all. Your query hides in a crowd of size k — and the tool prints the exact k for each lookup above, so you can verify the claim instead of trusting it.

Read the result honestly. “Not found” means not in this dataset. It is not a verdict that a password is strong, and a breach that was never published cannot appear here.

Expand (separate feature — different privacy model)

This is not the k-anonymity feature. The official Have I Been Pwned v3 breach API has no range mode for email addresses, so the full address is sent to the API, and the request needs a paid API key that you supply yourself. Nothing is hardcoded in this repo, and the key is held in memory only — it is never written to localStorage, a cookie, or the URL, and it is wiped after each request.

Scope: your own address only. Do not paste anyone else's.

Expect a CORS failure against the direct URL. haveibeenpwned.com deliberately sends no CORS headers, so browsers cannot call it directly regardless of key validity. Point “API base” at a small proxy of your own — see docs/hibp-proxy-example.md.

Scope & ethics. This tool checks only credentials the user personally owns and enters themselves. It must never be modified into a bulk-checker that runs lists of other people's emails, passwords, or NIK numbers — that crosses from a personal security tool into a tool for attacking others, which is illegal and out of scope for this project.
